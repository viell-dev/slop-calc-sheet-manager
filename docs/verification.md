# Verification map

What Sheet Manager promises, which checks show it, where they run, and what they do not show. Keep
this map current in the same pull request as any change to a promise or to its checks. Commands
are in
[CONTRIBUTING.md](https://github.com/viell-dev/slop-calc-sheet-manager/blob/main/CONTRIBUTING.md).

"CI" means the required jobs on every pull request and every push to `main`:

- two Checks jobs: Ruff, strict Pyright, unit tests, and two builds that must match byte for byte,
  on Python 3.12 and 3.14;
- three Linux headless jobs and three Linux gtk3 jobs, on LibreOffice 26.2.1, the newest 26.2, and
  the newest 26.8;
- the refusal job on 26.2.0;
- a Windows job on 26.8.

The jobs use official libreoffice.org builds pinned in `ci/libreoffice.json`.

"Windows desktop" means the separate **Windows desktop** workflow, which is not a required check:
real `SendInput` keyboard and mouse input to a visible Calc window with the `win` interface, on
GitHub's hosted Windows Server 2025 runner with one 1024×768 desktop at 96 DPI, the en-US layout,
no screen reader, and the Windows pin. It runs on pull requests that change the extension, the UI
suites or CI files, and by dispatch;
[CONTRIBUTING.md](https://github.com/viell-dev/slop-calc-sheet-manager/blob/main/CONTRIBUTING.md#visible-windows-desktop)
says what would make it required. Its evidence below is named with that workflow, never as CI.

Release-stage tests in `tests/unit/test_release_data.py` and `tests/unit/test_github_release.py`
title every stage, refuse beta and rc builds without their next-minor/major target and stable
releases with one, keep earlier title schemes valid in history and feeds, and check that the
Release workflow never defaults to stable. They retain numeric-order and feed-history checks; a
stage, a number or passing checks do not establish feature completeness or human usability.

`test_sheet_list.py:measure_large_workbook` records list opening and following at 1,000 sheets;
activation timing waits for selection and a rebuilt row model before starting the
separate tab-only measurement. These are measurements, not performance gates. Tab-only following
keeps the existing model; property changes can still require a full rebuild, whose cost is tracked
in #22.

`newer_selection_kept` queues real X input while the lab's main-thread callback runs, then
completes one recorded colour edit before returning. A native release observer proves that the
final Ctrl-click precedes repaint. This isolates delayed refresh from concurrent undo/modify
notifications; the intermittent selection-loss observation is tracked in #88.

The held-press checks (`selected_press_cursor`, `press_then_change`,
`newer_pick_survives_voided_press`) press through `Workbook.hold`. The tree selects the pressed row
natively, then VCL posts the mouse listeners' callback, which runs without the solar mutex, so a
selection does not show that the list has handled the press. An API activation made before then
records the list's input count without the press, and the list then rightly treats the press as
newer input and does not follow. That was #134's intermittent gen-session timeout. `hold` waits
for a probe listener to hear the press, then for a round trip to the main thread, which returns
only after that callback has finished; the probe alone is not enough, because listener containers
notify the most recently added listener first. `newer_pick_survives_voided_press` records the
list's selection, Calc's active sheet and tabs, the tree's focus, the held buttons and when the
press and release were heard at each step, with the container's monotonic clock, so that a
recurrence can be classified from `checks.json`.

The autoscroll check records viewport-height changes during its slow pointer glide. If a timed
notice expires and moves the bottom edge, it puts the pointer at the new edge once, then leaves
it stationary. The six-second scrolling budget, minimum movement and unchanged-order assertions
stay intact. A classified #90 harness reproduction kept the old pointer at Y=696 while the
viewport grew from 699 to 743 pixels; the old check failed, and tracking the actual edge passed.
The structural-clearing and save checks observe the panel notice, waiting for a preceding notice
to expire before establishing each case's selection.

## The checks themselves

A check that cannot see a failure is worse than none. The integration runner therefore fails a
session in each of these cases:

- **Nonzero exit or forced shutdown.** The office exits with a nonzero status, or has to be stopped
  after the 30-second grace period.
- **Fatal message.** The office logs LibreOffice's fatal-error message.
- **Crash dump.** The office leaves one of LibreOffice's own crash dumps. On Windows a crashed
  office exits with status 0
  ([#48](https://github.com/viell-dev/slop-calc-sheet-manager/issues/48)).
- **Stalled callback.** A callback on LibreOffice's main thread does not finish
  ([#50](https://github.com/viell-dev/slop-calc-sheet-manager/issues/50)).
- **Held terminate request.** The terminate request does not return, for example because a dialog
  holds it ([#40](https://github.com/viell-dev/slop-calc-sheet-manager/issues/40)).

The UI input helper disables keyboard repeat on the private Xvfb display, so a paused input
client cannot turn one intended tap into extra keys. `single_tap_after_client_pause` holds Down
for one second and checks exactly one cursor step. Timed operating-system repeat is not covered.

The Windows desktop workflow applies the same rules to its office session. Its input helper holds
each key for 50 ms, as a hand does: a 10 ms injected Esc did not cancel a native drag.

Only startup is retried, and never a test assertion. `tests/unit/test_office_process.py`,
`test_teardown.py`, and `test_stalled_cleanup.py` cover these rules against fakes.
